# 05. Data Model and Integrity Review

Source: `prisma/schema.prisma` (35 models), 14 migrations in `prisma/migrations/` (35 `CREATE TABLE`, 52 triggers, 216 constraints, 79 indexes). PostgreSQL stores everything; money is `numeric(18,2)`, quantities `numeric(18,4)`, rates `numeric(7,4)` / `numeric(8,5)`, timestamps `timestamptz`, business dates `date` (India business date, UTC+5:30). Almost every table carries `organization_id`. Mutable tables carry `version int` (optimistic concurrency) and `created_at` / `updated_at`. All foreign keys are `ON DELETE RESTRICT` except three cascades on session/role link tables (`Session.user`, `UserRole`/`RolePermission` links: `schema.prisma` lines 255, 266, 283).

## 4. Observations and risks

1. **Invoice has no due date or terms fields**, so ageing, reminders and terms printing are impossible without a schema change.
2. **No invoice drafts.** The data model has no pre-posting document.
3. **Seller GSTIN is copied into every invoice** (`seller_gstin`) correctly, but customer/seller snapshot fields mean address history is only in invoices, not a separate address-history table.
4. **`audit_logs` has no retention or export path** and no read API (R-063).
5. **Single warehouse in practice**: `warehouse_id` is on every movement, but only the primary warehouse is created and used by invoices (`facts.ts` picks the primary).
6. **Quantity precision** is governed by `units.decimal_places` while the column keeps four places; changing a unit's decimals after stock exists is not guarded beyond the product trigger that forbids changing a unit once stock exists.
7. **Backup manifest table limit of 100** (`manifest.ts`); the schema has 35 tables, so roughly 65 more can be added before the limit must be raised.
